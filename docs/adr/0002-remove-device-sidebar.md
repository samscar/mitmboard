# 移除设备栏，按设备筛选改用 `device:` 过滤

**Status**: accepted

原界面左侧有设备栏、顶层有 Devices 与 Dashboard 两页，这是上游 Proxino 的结构。Charles 没有对应物，且两页的价值主要是统计汇总，与「边看流量边调试」的主线相去甚远。决定移除设备栏与这两个顶层页，顶层只留 Inspector；按设备筛选改用 `device:` 过滤表达式（与既有 `client:` 同义，保留 `client:` 兼容已保存的过滤条件）并带已知设备的自动补全，直通列表改为顶栏标签点开的弹窗。

代价是失去「点一下就切到某台设备」和「在 UI 里给设备改名」两个入口，后端的改名接口保留不动。另一个限制是设备身份仍是来源 IP：场景 A 里两台手机若经同一 AP 或热点 NAT 出去，`device:` 无法区分它们，要等分流器落地才能按连接来源分开。

## Considered Options

- **保留设备栏**：切换设备最快，但与 Charles 布局不一致，且场景 B（无图形界面的云主机）里用户对「设备」的兴趣远低于对 host 的兴趣。
- **只删 Dashboard、保留 Devices 页**：统计仍有承载，但顶层导航仍多一个与调试主线无关的页面，认知负担只减一半。
- **保留设备栏但折叠**：多一个中间状态，测试面与状态组合都增加，收益不足以支撑。

## Consequences

- 同出口 IP 的多设备在分流器实现前不可区分，这一限制写进 `docs/v1-scope.md`。
- 设备手动改名的前端入口消失，`PUT /api/clients/{ip}` 保留。
- 依赖设备分组的旧前端测试随功能移除而删除或改写，Playwright 冒烟选择器跟随布局变化修正。
